# C28E Issue Repair Matrix

This branch is code-review first. It fixes the blueprint-mechanism gaps before any new full experiment is run.

| Issue | C28D Problem | C28E Code Fix | Review Target |
|---|---|---|---|
| PR scope polluted | PR #8 was based on `main`, so historical/C28C files appeared in the diff | Branch from `c28c-cleanroom-e2e-blueprint-v2`; open PR against that base | GitHub PR changed-files scope |
| Candidate eval truncation | `hard_negative_k + 1` truncated eval candidates | `candidate_topk_train`, `candidate_topk_eval`, and `eval_candidate_k` are separate | `engine/train.py`, `engine/evaluate.py` |
| Candidate duration bug | Wrong candidate videos reused query/GT video duration | Candidate proposals use `video_id -> duration` from video metadata and per-candidate span masks | `data/video_bank.py`, `data/proposal_dataset.py`, `data/collate.py` |
| Fake moment-aware label | `use_moment_aware_bank` existed but final weight was `0.0` | C28E uses real clip visual/subtitle/joint late interaction | `engine/c28e_late_interaction.py` |
| No clip-level retrieval | Retriever was global query embedding to global video mean embedding | Two-stage current-student pooled broad topK then clip-level rerank topK is used in both C28E replay and full train/eval candidate refresh | `two_stage_retrieve`, `engine/refresh_hard_negatives.py` |
| Padding pollution | Sequence banks padded/truncated to 64 clips but temporal mixing and span pooling ignored valid-clip masks | Visual/subtitle/joint clip masks are applied before temporal mixing and inside pooled, PREM/REG/AMD, late softTopK, token MaxSim, and span-pooling paths | `data/*_bank.py`, `models/video_encoder.py`, `models/full_model.py`, `utils/tensor_ops.py` |
| Long-video blindness | Fixed 64 clips represented only the first ~96 seconds and GT insertion used fixed 1.5s bins | Long release sequences are mean-bin-resampled into 64 duration-aware bins; `TemporalGrid` maps clips to the full video duration and GT span insertion uses that mapping | `data/temporal_grid.py`, `data/*_bank.py`, `data/proposal_dataset.py` |
| Video encoder bypass | Pre-encoded banks in training would prevent video encoder gradients | Training scores raw candidate clips through `VideoSubtitleEncoder` | `late_scores_for_raw_candidates` |
| Monolithic GPU candidate tensor | Raw scoring used one `B x C x T x D` tensor, risking OOM and tempting candidate reduction | Candidate scoring is chunked with `candidate_encode_chunk` while preserving `candidate_topk_train=200` | `late_scores_for_raw_candidates` |
| Retriever-only branch | C28E late score existed outside the full VCMR graph | C28E-3 now runs full E2E training through `run_full_training`/`compute_full_loss`; retriever replay remains diagnostic only | `run_c28e_clip_late_interaction_retriever.py`, `engine/train.py` |
| Late score side-channel | Full model kept pooled `visual_sim/subtitle_sim/joint_sim` as localizer inputs even when late score existed | Late visual/subtitle/joint sims replace the localizer retrieval evidence and wrong-video risk is recomputed from late sims | `models/full_model.py`, `models/retrieval_guided_localizer.py` |
| Query-only active moment | ActiveMoment produced identical temporal priors for every candidate video | ActiveMoment is conditioned on query, candidate `joint_pool`, and their interaction; diversity loss supports `[B,C,A]` anchors | `models/active_moment.py`, `losses/active_moment_loss.py` |
| Broad-stage blind spot | Late rerank could not reveal whether GT was already absent from pooled broad topK | Replay reports broad pooled rank metrics separately from late rerank metrics | `two_stage_retrieve` |
| Missing curriculum | Candidate mix was fixed teacher/student/random, not the requested staged curriculum | Full E2E candidate refresh schedules teacher warm-start down across epochs while student late-aware mining remains active, and logs the phase per epoch | `engine/train.py`, `engine/refresh_hard_negatives.py` |
| Query padding in miner | Full candidate refresh encoded padded query tokens without mask | `refresh_candidates` now passes query masks to the query encoder | `engine/refresh_hard_negatives.py` |
| Train metric selection | Best checkpoint used train `VR@100` or full training had `best_select=None` | Full E2E checkpoints are selected on `calib_select` using VCMR R@1/5/10 IoU0.7, VR@100, and wrong-video penalty | `engine/train.py` |
| Holdout leakage risk | Holdout was repeatedly used for gate/sweeps | Holdout final stage requires `--allow_holdout_final` | `run_c28e_clip_late_interaction_retriever.py` |
| Weak teacher distillation | Teacher score direction was assumed when present | Rank-derived teacher logits are the default; raw score use is opt-in via config after schema audit | `engine/c28e_late_interaction.py`, `configs/c28e_code_review.yaml` |
| Config mechanism drift | C28E config advertised retriever-only distillation loss names even though the full runner did not consume them | C28E config now exposes explicit full E2E loss weights; retriever-only loss defaults stay inside the diagnostic helper | `configs/c28e_code_review.yaml`, `losses/full_loss.py` |
| Missing in-batch negatives | Full retriever loss used candidate-set negatives but did not include cross-query video negatives required by the blueprint | `compute_full_loss` now adds `L_inbatch_retrieval`, using each batch item GT candidate as a positive and other batch positives as negatives while treating duplicate GT videos as multi-positive | `losses/retrieval_loss.py`, `losses/full_loss.py`, `configs/c28e_code_review.yaml` |
| Resume report overwrite | Resume overwrote prior logs | Full E2E training log, best selection score, and best checkpoint metadata are loaded and appended on resume | `engine/train.py` |
| False ablation evidence | Placeholder ablation summary could imply contribution without toggled runs | Ablation summary now reports insufficient evidence until A4/A5/A6/A12 toggled results exist | `ablation/run_ablation.py`, `ablation/contribution_table.py` |
| Legacy helper ambiguity | Pooled miner and retriever-only trainer could be mistaken for the C28E main path | Legacy miner/retriever training are labeled diagnostic-only; C28E-3 owner is `run_full_training` with `compute_full_loss` | `data/dynamic_candidate_miner.py`, `engine/c28e_late_interaction.py`, `run_c28e_clip_late_interaction_retriever.py` |
| Naming/report confusion | C28D reports reused C28D-1 names under later stages | C28E stages and report names are C28E-specific | `run_c28e_clip_late_interaction_retriever.py` |
| Premature/reduced execution | Full E2E could be skipped in favor of retriever-only shortcuts | Runner stage C28E-3 is the full model owner; holdout is still guarded and no proposal/candidate count is reduced for memory | C28E runner stages |
